Scenario

You are building a Serverless Sales Dashboard. When a CSV file is uploaded to an S3 bucket, a Lambda function is automatically triggered to process the file and generate a consolidated JSON report. A static website hosted on S3 reads and displays the output data in real-time.

Upload sales.csv to S3 "uploads/"
↓
S3 event notification triggers AWS Lambda
↓
Lambda reads CSV, calculates metrics, and writes results.json to "data/"
↓
Static website updates and displays dashboard from results.json
System Integrity Alert: The base Lambda source code provided has exactly 3 bugs. Your core assignment is to deploy the infrastructure pipeline, find the bugs using Amazon CloudWatch Logs, and successfully remediate them.

Step-by-Step Instructions

Step 1: Create S3 Bucket

Construct a globally unique S3 bucket with the following exact specifications:

  • Name: cldcomp-interim-<yourlastname> (e.g., cldcomp-interim-santos)
  • Region: ap-southeast-1
  • Public access: Allowed (Uncheck "Block all public access")
  • Static website hosting: Enabled (Set Index document to index.html)

Step 2: Set Bucket Policy

Apply a bucket policy allowing public read permissions across all contained objects. Navigate to Bucket → Permissions → Bucket policy → Edit, and inject the following snippet (ensuring you substitute <yourlastname>):

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::cldcomp-interim-<yourlastname>/*"
    }
  ]
}

Step 3: Upload Website Source Files

  1. Create two directories inside your bucket root: uploads/ and data/.
  2. Fetch the core webpage markup from: https://raw.githubusercontent.com/johnwilben/CLDCOMP/main/index.html
  3. Open the file locally and swap out [YOUR FULL NAME HERE] with your actual full name.
  4. Upload this modified index.html file directly into the root level of your bucket.
  5. Test the setup by browsing to the S3 static URL. It should load correctly and display a "Loading data..." indicator.

Step 4: Create Lambda Function

Provision a new Lambda environment configured as follows:

  • Name: cldcomp-interim-<yourlastname>-processor
  • Runtime: Python 3.12
  • Architecture: x86_64
  • Execution role: Choose "Create a new role with basic Lambda permissions".

Pull the base processor code from: https://raw.githubusercontent.com/johnwilben/CLDCOMP/main/lambda_function.py, replace the starter boilerplate inside the editor, and click Deploy.

Step 5: Configure Lambda IAM Role Policy

Your processing function requires custom permissions to access data items inside the S3 environment. Attach an inline policy:

  1. Inside the Lambda interface, open the Configuration tab → Permissions.
  2. Click the active Role name link to navigate to the IAM Identity Management dashboard.
  3. Select Add permissions → Create inline policy and switch over to the JSON view.
  4. Inject the localized scope block below (ensure to update <yourlastname>):
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::cldcomp-interim-<yourlastname>/uploads/*"
    }
  ]
}
  1. Advance via Next, give the policy a descriptive name of s3-access-policy, and finalize by selecting Create policy.
Important Note: This template provides read capabilities exclusively. This constraint is deliberate; you are expected to update this policy during debugging.

Step 6: Add S3 Bucket Trigger Link

Establish a native integration binding within your Lambda function workspace:

  • Source Component: S3 Bucket
  • Target Bucket: Select your specific cldcomp-interim-<yourlastname> bucket
  • Event Type: All object create events (s3:ObjectCreated:*)
  • Prefix Filter: uploads/
  • Suffix Filter: .csv

Step 7: Execute First System Test Run

  1. Download the dataset template: https://raw.githubusercontent.com/johnwilben/CLDCOMP/main/sales.csv
  2. Upload sales.csv into the uploads/ directory inside your S3 bucket.
  3. Allow 10–15 seconds for processing pipelines to clear.
  4. Refresh your web dashboard application. Check whether data has hydrated the summary table elements. If it continues to display a loading state, continue to Step 8.

Step 8: System Debugging Protocol

Your production pipeline contains 3 discrete logic and permission bugs. Open up CloudWatch Logs to find traces and solve the problems.

Log Group Location: CloudWatch → Log groups → /aws/lambda/cldcomp-interim-<yourlastname>-processor

Debugging Clues:

  • Bug 1 (IAM Exception): Scan log files for an AccessDenied statement. While the function reads successfully from the bucket, it is failing at a secondary interaction. Rectify the inline IAM policy configuration without assigning unsafe universal privileges. Do not grant S3FullAccess.
  • Bug 2 (Key Mapping Exception): Look for a KeyError crash dump within the log outputs. The Python pipeline addresses a data column handle that deviates from the structured headers in the source sales.csv spreadsheet. Isolate and synchronize the column keys.
  • Bug 3 (Output Desynchronization): CloudWatch shows successful completion traces with zero runtime exceptions, yet the web dashboard remains empty. The parsing script commits the structural output back into the bucket but introduces a filename variation differing from what the dashboard scripts look for.
Workflow Note: For adjustments inside your Lambda text editor, click Deploy before re-uploading the sales.csv payload. For identity structure adjustments in IAM, simply upload the CSV file again to trigger execution.

Step 9: Success Validation Checklist

Your solution is complete when:

  • The compiled report data/results.json appears inside your storage bucket.
  • The web interface loads metrics reflecting correct aggregate values and item tracking datasets.
